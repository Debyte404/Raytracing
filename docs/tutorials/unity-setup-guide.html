🎮 Unity Setup for Complete Beginners

Everything you need to know to run the ray tracer — from fixing the code editor error to understanding how scenes work.

🔧 Fixing the "External Code Editor" Error

Unity is trying to open your C# scripts in JetBrains Rider, but it's not installed at the path Unity expects. Here's how to fix it:

  1. Open Unity's Preferences
    Go to Edit → Preferences (Windows) or Unity → Settings (Mac).
    [Unity Preferences Window]
  2. Go to External Tools
    Click "External Tools" in the left sidebar.
  3. Choose your code editor
    In the "External Script Editor" dropdown, select one of:
    • Visual Studio (if installed — recommended for beginners)
    • Visual Studio Code (lightweight, free)
    • Notepad++ (simple text editor)
    • Or click "Browse..." and find your preferred editor
  4. Click "Regenerate project files"
    This makes Unity recreate the .csproj files so your editor understands the project.

💡 Recommendation for Beginners

Download Visual Studio Community (free) from Microsoft's website. It's the easiest option for Unity development and has the best integration.

📁 Understanding the Unity Project Structure

Your project folder contains these important folders:

📂 Assets/

ALL your game files live here:
• Scripts (C# files)
• Shaders (.compute files)
• Models, textures, sounds
• Scenes (.unity files)

📂 Scenes/

A "Scene" is like a level or a room. It contains:
• GameObjects (camera, lights, etc.)
• Their positions and settings
• Scripts attached to them

⚠️ Never Touch These Folders

Don't manually edit files in Library/, Temp/, or Logs/. They're generated by Unity and will be overwritten.

🎯 Step-by-Step: Running the Ray Tracer

Step 1: Create the Compute Shader

  1. In Unity's Project window (bottom panel), right-click in the Assets folder.
  2. Select Create → Shader → Compute Shader
  3. Name it "RayTracingShader" and press Enter.
  4. Double-click it to open in your code editor.
  5. Replace ALL the content with the code from the RayTracingShader.compute file.
  6. Save the file (Ctrl+S).

🎯 What is a Compute Shader?

A compute shader is a program that runs on your GPU (graphics card) instead of your CPU. It can run thousands of calculations in parallel — perfect for processing every pixel on screen at once.

Step 2: Create the C# Script

  1. In the Project window, right-click in Assets.
  2. Select Create → C# Script
  3. Name it "RayTracingMaster" (the name MUST match the class name inside!).
  4. Double-click it to open in your code editor.
  5. Replace ALL the content with the code from the RayTracingMaster.cs file.
  6. Save the file (Ctrl+S).

Step 3: Set Up the Scene

  1. In the Hierarchy window (left panel), find "Main Camera".
  2. Click on Main Camera to select it.
  3. In the Inspector window (right panel), click "Add Component".
  4. Type "RayTracingMaster" and click it.
  5. You should see a new component appear on the Camera with these fields:
    • Ray Tracing Shader (empty slot)
    • Render In Scene View (checked)
    • Add Test Sphere (checked)

Step 4: Link the Shader

  1. With Main Camera still selected, look at the RayTracingMaster component.
  2. Drag "RayTracingShader" from the Project window into the "Ray Tracing Shader" slot.
  3. OR click the small circle on the right of the slot and select it from the list.
[Inspector showing RayTracingMaster with shader assigned]

Step 5: Press Play!

  1. Click the Play button (▶) at the top center of Unity.
  2. In the Game view (tab next to Scene), you should see:
    • A sky gradient (blue at top, darker at bottom)
    • A red sphere in the center
    • A chrome sphere to the left
    • A bright light sphere above
  3. Move the camera using WASD + mouse (if you have a camera controller) or by selecting the camera and changing its Position in the Inspector.

🖥️ Scene View Toggle

The script has a built-in toggle for rendering in Scene View:

C# 
[ExecuteInEditMode]              // Makes script run without pressing Play
[ImageEffectAllowedInSceneView]  // Allows OnRenderImage in Scene View
public class RayTracingMaster : MonoBehaviour
{
    public bool renderInSceneView = true;  // Toggle in Inspector!
}

To use it:

  • Checked (true): You'll see the ray-traced output in the Scene view even without pressing Play
  • Unchecked (false): Scene view shows normal Unity rendering (easier to position objects)

🎯 Pro Tip

Keep "Render In Scene View" OFF while editing your scene (so you can see wireframes and gizmos), then turn it ON to preview the ray-traced result without entering Play mode.

🧠 Understanding Camera-to-World (The Simple Version)

This is the part that confuses everyone. Let me break it down super simply:

The Problem

Your screen is 2D (pixels have x, y). Your game world is 3D (objects have x, y, z). How do you turn a pixel into a direction in 3D space?

🎬 Analogy: A Movie Projector in Reverse

Imagine a movie projector:

• Film = your 2D screen (pixels)
• Lens = the projection matrix (squashes 3D into 2D)
• Screen = what the player sees

Ray tracing does the opposite: it starts from the screen and goes BACK through the lens to figure out what 3D direction each pixel represents.

The Two Matrices

📐 Projection Matrix

This is like your camera lens. It defines:

• Field of view (how wide the camera sees)
• Aspect ratio (screen width / height)
• Near/far clip planes

It squashes 3D into 2D.

🌍 View Matrix

This is your camera's position and rotation. It defines:

• Where the camera is (x, y, z)
• Which way it's facing
• Which way is "up"

It converts world space → camera space.

What We Need: The INVERSE Matrices

Normal rendering goes: World → Camera → Screen

Ray tracing needs the reverse: Screen → Camera → World

pixel (2D) → inverse projection → camera direction (3D)
camera direction → inverse view → world direction (3D)

What the Code Actually Does

HLSL 
Ray CreateRay(float2 uv)
{
    // 1. Pixel [0,1] → Screen space [-1,1]
    //    Like saying "center of screen = (0,0)"
    float3 ndc = float3(uv * 2.0f - 1.0f, 1.0f);
    
    // 2. "Un-squash" using inverse projection
    //    Converts 2D screen pos back to 3D camera direction
    float4 viewPos = mul(_CameraInverseProjection, float4(ndc, 1.0f));
    viewPos = viewPos / viewPos.w;  // Perspective fix
    
    // 3. Convert from "camera-relative" to "world-relative"
    //    Like rotating the direction to match where camera is facing
    float3 worldDir = mul(_CameraToWorld, float4(viewPos.xyz, 0.0f)).xyz;
    worldDir = normalize(worldDir);
    
    // 4. Camera position is stored in the matrix
    float3 worldOrigin = _CameraToWorld._m03_m13_m23;
    
    Ray ray;
    ray.origin = worldOrigin;      // Ray starts at camera
    ray.direction = worldDir;       // Ray goes in calculated direction
    return ray;
}

🧠 The One-Sentence Summary

_CameraInverseProjection turns a pixel into "which direction relative to the camera?" and _CameraToWorld turns that into "which direction in the actual 3D world?"

🐛 Common Errors & Fixes

❌ "unrecognized identifier 'Ray'"

Cause: In HLSL, structs must be defined BEFORE they're used.

Fix: Move the struct Ray { ... } to the TOP of the file, before any functions that use it.

❌ "No Camera found!"

Cause: The script is on a GameObject that doesn't have a Camera component.

Fix: Attach the script ONLY to the Main Camera GameObject.

❌ Screen is black / no output

Cause 1: The shader slot is empty in the Inspector.

Fix: Drag the compute shader into the "Ray Tracing Shader" field.

Cause 2: The camera is inside an object.

Fix: Check camera Position in Inspector — make sure it's at (0, 1, -10) or similar.

❌ "Struct size mismatch" or weird colors

Cause: C# struct doesn't match HLSL struct size.

Fix: Both structs must be exactly 64 bytes. Use padding floats to align to 16-byte boundaries.
