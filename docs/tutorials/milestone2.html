Milestone 2 — Intersection Testing

The Perfect Sphere

Learn the quadratic formula approach to ray-sphere intersection — the fundamental geometric test in ray tracing.

🎯 What You'll Build

A solid white sphere floating in the void. Rays that hit the sphere turn white; rays that miss stay black (or show a sky gradient). This proves your intersection math is correct.

Interactive: Move your mouse to aim rays from the camera. Watch how rays either hit the sphere (pink dot) or miss (fade out). The quadratic discriminant determines hit/miss.

📐 Core Concepts

1. The Sphere Equation

A sphere is all points at a fixed distance (radius) from a center point. In math:

|p - center|² = radius²

Where p is any point on the surface, center is the sphere's position, and radius is... the radius.

💡 Intuition

Imagine a bubble. Every point on the bubble's surface is exactly the same distance from the bubble's center. That's what this equation says — the distance (|p - center|) equals the radius.

2. Ray-Sphere Intersection

We want to find: does our ray hit the sphere? And if so, WHERE?

A ray is: r(t) = origin + t·direction (t ≥ 0)

A sphere is: |p - center|² = radius²

Substitute the ray equation into the sphere equation:

|origin + t·direction - center|² = radius²

Let oc = origin - center (vector from center to ray origin)

|oc + t·direction|² = radius²

(oc + t·direction)·(oc + t·direction) = radius²

oc·oc + 2t(oc·direction) + t²(direction·direction) = radius²

t²(direction·direction) + 2t(oc·direction) + (oc·oc - radius²) = 0

This is a quadratic equation in the form at² + bt + c = 0:

a = direction · direction (= 1 if normalized)
b = 2 · (oc · direction)
c = oc · oc - radius²

3. The Quadratic Formula & Discriminant

The solutions are:

t = (-b ± √(b² - 4ac)) / 2a

The term under the square root — b² - 4ac — is called the discriminant (Δ). It tells us everything:

🔍 What the Discriminant Tells Us

• Δ < 0: No real solutions → Ray misses the sphere completely
• Δ = 0: One solution → Ray grazes the sphere (tangent)
• Δ > 0: Two solutions → Ray enters and exits the sphere

🎯 Why Two Solutions?

A ray passing through a sphere hits it TWICE: once entering (front face) and once exiting (back face). We always want the NEAREST hit (smallest positive t), because that's what the camera sees first.

💻 Implementation

HLSL Sphere Structure & Intersection

HLSL 
// Sphere data structure - must match C# struct layout exactly
struct Sphere
{
    float3 position;
    float radius;
    float3 albedo;
    float pad0;      // Padding for 16-byte alignment
    float3 specular;
    float pad1;      // Padding for 16-byte alignment
};

// Ray structure
struct Ray
{
    float3 origin;
    float3 direction;
};

// Hit information returned from intersection tests
struct RayHit
{
    float3 position;    // Where the ray hit
    float distance;     // Distance from ray origin
    float3 normal;      // Surface normal at hit point
    float3 albedo;      // Surface color
    float3 specular;    // Specular color
};

// Create a "miss" hit (no intersection)
RayHit CreateRayHit()
{
    RayHit hit;
    hit.position = float3(0.0f, 0.0f, 0.0f);
    hit.distance = 1.#INF;        // Infinity = no hit
    hit.normal = float3(0.0f, 0.0f, 0.0f);
    hit.albedo = float3(0.0f, 0.0f, 0.0f);
    hit.specular = float3(0.0f, 0.0f, 0.0f);
    return hit;
}

// Test ray-sphere intersection using quadratic formula
void IntersectSphere(Ray ray, Sphere sphere, inout RayHit bestHit)
{
    // Vector from sphere center to ray origin
    float3 oc = ray.origin - sphere.position;
    
    // Quadratic coefficients
    float a = dot(ray.direction, ray.direction);  // = 1 if normalized
    float b = 2.0f * dot(oc, ray.direction);
    float c = dot(oc, oc) - sphere.radius * sphere.radius;
    
    // Discriminant: b² - 4ac
    float discriminant = b * b - 4.0f * a * c;
    
    // No intersection if discriminant < 0
    if (discriminant < 0.0f)
        return;
    
    // Calculate both intersection distances
    float sqrtDisc = sqrt(discriminant);
    float t1 = (-b - sqrtDisc) / (2.0f * a);  // Entry point (closer)
    float t2 = (-b + sqrtDisc) / (2.0f * a);  // Exit point (farther)
    
    // We want the nearest positive intersection
    float t = t1;
    if (t < 0.0f)   // If entry is behind camera, use exit
        t = t2;
    if (t < 0.0f)   // If both are behind, no visible hit
        return;
    
    // Only update if this hit is closer than previous best
    if (t < bestHit.distance)
    {
        bestHit.distance = t;
        bestHit.position = ray.origin + t * ray.direction;
        bestHit.normal = normalize(bestHit.position - sphere.position);
        bestHit.albedo = sphere.albedo;
        bestHit.specular = sphere.specular;
    }
}

C#: Passing Sphere Data to GPU

C# 
using UnityEngine;

// Must exactly match HLSL struct layout (16-byte aligned)
public struct Sphere
{
    public Vector3 position;
    public float radius;
    public Vector3 albedo;
    public float pad0;    // Padding
    public Vector3 specular;
    public float pad1;    // Padding
}

public class RayTracingMaster : MonoBehaviour
{
    public ComputeShader rayTracingShader;
    private RenderTexture target;
    private Camera mainCamera;
    
    // Compute buffer to hold sphere data on GPU
    private ComputeBuffer sphereBuffer;
    // Array of spheres to render
    private Sphere[] spheres;

    void Awake()
    {
        mainCamera = GetComponent<Camera>();
        InitSpheres();
    }

    void InitSpheres()
    {
        // Create one test sphere
        spheres = new Sphere[1];
        spheres[0] = new Sphere()
        {
            position = new Vector3(0, 0, 5),   // 5 units in front of camera
            radius = 1.5f,
            albedo = new Vector3(1, 1, 1),     // White
            specular = new Vector3(0, 0, 0)
        };

        // Create compute buffer: count, stride (bytes per sphere)
        // sizeof(float3) + sizeof(float) + sizeof(float3) + sizeof(float) + sizeof(float3) + sizeof(float)
        // = 12 + 4 + 12 + 4 + 12 + 4 = 48 bytes per sphere
        sphereBuffer = new ComputeBuffer(spheres.Length, 48);
        sphereBuffer.SetData(spheres);
    }

    void SetShaderParameters()
    {
        rayTracingShader.SetMatrix("_CameraToWorld", 
            mainCamera.cameraToWorldMatrix);
        rayTracingShader.SetMatrix("_CameraInverseProjection", 
            mainCamera.projectionMatrix.inverse);
        
        // Pass sphere buffer to shader
        rayTracingShader.SetBuffer(0, "_Spheres", sphereBuffer);
        rayTracingShader.SetInt("_SphereCount", spheres.Length);
    }

    void OnDestroy()
    {
        // ALWAYS release compute buffers to prevent memory leaks
        if (sphereBuffer != null)
            sphereBuffer.Release();
    }
    
    // ... OnRenderImage and Render methods from Milestone 1 ...
}

Updated Shader Kernel

HLSL 
// Buffer of spheres passed from CPU
StructuredBuffer<Sphere> _Spheres;
int _SphereCount;

// Trace a ray against all spheres and return the closest hit
RayHit TraceRay(Ray ray)
{
    RayHit bestHit = CreateRayHit();
    
    // Test against every sphere
    for (int i = 0; i < _SphereCount; i++)
    {
        IntersectSphere(ray, _Spheres[i], bestHit);
    }
    
    return bestHit;
}

// Main entry point
[numthreads(8, 8, 1)]
void MainRayGen(uint3 id : SV_DispatchThreadID)
{
    uint width, height;
    Result.GetDimensions(width, height);
    
    float2 uv = float2(id.x / (float)width, id.y / (float)height);
    
    // Generate ray
    Ray ray = CreateRay(uv);
    
    // Trace against scene
    RayHit hit = TraceRay(ray);
    
    // Shade: white if hit, black if miss
    float3 color = hit.distance < 1.#INF ? hit.albedo : float3(0, 0, 0);
    
    Result[id.xy] = float4(color, 1.0f);
}

🎯 Key Insight

The inout keyword in HLSL means the parameter is passed by reference — modifications inside the function affect the caller's variable. We use this to update bestHit only when we find a closer intersection.

🧮 The Math Deep Dive

Why does the discriminant work?

The discriminant b² - 4ac comes from completing the square of the quadratic. Geometrically:

🔍 Geometric Interpretation

• Δ < 0: The ray passes "beside" the sphere — closest approach is still farther than radius
• Δ = 0: The ray just grazes the sphere — closest approach equals radius
• Δ > 0: The ray's path takes it through the sphere's interior

The "oc" Vector Trick

Instead of computing (origin - center) repeatedly, we store it as oc. This:

  • Saves computation (dot products are expensive)
  • Makes the code cleaner
  • Matches the standard reference implementation

Why check t < 0?

If both intersection points are behind the ray origin (t < 0), the sphere is behind the camera. We must reject these hits because we can't see behind us!

🐛 Common Bug

If your sphere appears "inside out" or normals look wrong, check that you're computing normalize(hit.position - sphere.position) and NOT normalize(sphere.position - hit.position). The normal must point OUTWARD from the sphere surface.

✅ Verification

You should see:

  • A white circle on a black background
  • The circle stays centered when you move the camera forward/back
  • Moving left/right makes the circle shift (parallax)
  • Getting very close makes the circle fill the screen

📚 What You Learned

🎓 Key Takeaways

• Sphere equation: all points at distance r from center c
• Ray-sphere intersection becomes a quadratic equation
• The discriminant tells us hit/miss without computing full solutions
• We always want the nearest positive t value
• ComputeBuffers transfer structured data from CPU to GPU
• Struct layout must match exactly between C# and HLSL (16-byte aligned)
