Milestone 1 — Ray Generation

The Infinite Void

Learn how to map 2D screen pixels to 3D world rays using camera matrices. This is the foundation of all ray tracing.

🎯 What You'll Build

A compute shader that generates a dynamic gradient on screen. As you rotate the camera, the gradient shifts — proving that each pixel is correctly mapped to a 3D direction vector.

Interactive Visualization: Drag to rotate the camera. Watch how each pixel (blue dots) shoots a ray (cyan lines) into the scene. The color gradient shows the ray direction.

📐 Core Concepts

1. What is a Ray?

A ray is a half-infinite line starting from a point and traveling in a direction. In ray tracing, we shoot one ray from the camera through each pixel on the screen into the 3D world.

r(t) = origin + t · direction,   where t ≥ 0

💡 Think of it like this

Imagine standing in a dark room with a laser pointer. The laser starts at your hand (origin) and shoots in a straight line (direction). In ray tracing, we do this millions of times per frame — once for every pixel on your screen.

2. The Camera-to-World Transformation

Your screen is 2D (pixels have x, y coordinates), but your scene is 3D. We need to "unproject" each pixel into a 3D ray direction.

🔄 The Pipeline

Pixel coordinates (2D) → Normalized Device Coordinates (NDC) → Clip Space → View Space → World Space

Here's the step-by-step transformation:

  1. Pixel to UV: Convert pixel coordinates (0 to width, 0 to height) to UV coordinates (0 to 1).
    uv = pixelCoord / screenSize
  2. UV to NDC: Convert UV to Normalized Device Coordinates (-1 to 1). Note: Y is flipped because screen Y goes down, but 3D Y goes up.
    ndc = (uv * 2 - 1) with Y flipped
  3. NDC to Clip Space: Add a Z value of 1 (far plane) and W of 1.
    clip = (ndc.x, ndc.y, 1, 1)
  4. Clip to View Space: Multiply by the inverse projection matrix.
    view = inverseProjection · clip
  5. View to World Space: Multiply by the inverse view matrix.
    worldDir = normalize(inverseView · view)

View Matrix

The View Matrix transforms world coordinates to camera space. Its rows contain:

  • Row 1 (R): Camera's Right vector
  • Row 2 (U): Camera's Up vector
  • Row 3 (F): Camera's Forward vector
  • Row 4 (P): Camera's Position

The Projection Matrix maps 3D view space to 2D clip space, accounting for field of view and aspect ratio.

💻 Implementation

C# Script (RayTracingMaster.cs)

This script runs on the CPU. It sets up the compute shader and passes camera data every frame.

C# 
using UnityEngine;

public class RayTracingMaster : MonoBehaviour
{
    // The compute shader asset - assign in Inspector
    public ComputeShader rayTracingShader;
    
    // Render texture to store the output
    private RenderTexture target;
    
    // Camera component reference
    private Camera mainCamera;

    void Awake()
    {
        mainCamera = GetComponent<Camera>();
    }

    // Unity calls this after all rendering is done
    void OnRenderImage(RenderTexture source, RenderTexture destination)
    {
        SetShaderParameters();
        Render(destination);
    }

    void SetShaderParameters()
    {
        // Pass camera matrices to the shader
        // _CameraToWorld = inverse view matrix
        rayTracingShader.SetMatrix("_CameraToWorld", 
            mainCamera.cameraToWorldMatrix);
        
        // _CameraInverseProjection = inverse projection matrix
        rayTracingShader.SetMatrix("_CameraInverseProjection", 
            mainCamera.projectionMatrix.inverse);
    }

    void Render(RenderTexture destination)
    {
        // Create render texture if it doesn't exist
        if (target == null || target.width != Screen.width 
            || target.height != Screen.height)
        {
            if (target != null) target.Release();
            
            target = new RenderTexture(Screen.width, Screen.height, 0,
                RenderTextureFormat.ARGBFloat, RenderTextureReadWrite.Linear);
            target.enableRandomWrite = true;
            target.Create();
        }

        // Set the target texture
        rayTracingShader.SetTexture(0, "Result", target);
        
        // Dispatch compute shader - one thread per pixel
        int threadGroupsX = Mathf.CeilToInt(Screen.width / 8.0f);
        int threadGroupsY = Mathf.CeilToInt(Screen.height / 8.0f);
        rayTracingShader.Dispatch(0, threadGroupsX, threadGroupsY, 1);

        // Blit result to screen
        Graphics.Blit(target, destination);
    }
}

🎯 Key Insight

OnRenderImage is a Unity callback that runs after the camera renders. We intercept this to inject our compute shader output. The [8,8,1] thread group size is standard for compute shaders — each group processes an 8×8 tile of pixels.

HLSL Compute Shader (RayTracingShader.compute)

This runs on the GPU, once per pixel, in parallel.

HLSL 
// Each thread group is 8x8 pixels
#pragma kernel MainRayGen

// Output texture
RWTexture2D<float4> Result;

// Camera matrices passed from C#
float4x4 _CameraToWorld;
float4x4 _CameraInverseProjection;

// Generate a ray from camera through this pixel
Ray CreateRay(float2 uv)
{
    // Transform from UV [0,1] to NDC [-1,1]
    // Flip Y: screen Y goes down, but NDC Y goes up
    float3 ndc = float3(uv * 2.0f - 1.0f, 1.0f);
    ndc.y = -ndc.y;

    // Transform to view space: multiply by inverse projection
    float4 viewPos = mul(_CameraInverseProjection, float4(ndc, 1.0f));
    
    // Perspective divide (convert from homogeneous coordinates)
    viewPos = viewPos / viewPos.w;
    
    // Transform to world space and get direction
    float3 worldDir = mul(_CameraToWorld, float4(viewPos.xyz, 0.0f)).xyz;
    worldDir = normalize(worldDir);

    // Camera position is in the last row of _CameraToWorld
    float3 worldOrigin = _CameraToWorld._m03_m13_m23;

    Ray ray;
    ray.origin = worldOrigin;
    ray.direction = worldDir;
    return ray;
}

// Main compute shader entry point
[numthreads(8, 8, 1)]
void MainRayGen(uint3 id : SV_DispatchThreadID)
{
    // Get screen dimensions
    uint width, height;
    Result.GetDimensions(width, height);

    // Convert thread ID to UV coordinates [0, 1]
    float2 uv = float2(id.x / (float)width, id.y / (float)height);

    // Create ray for this pixel
    Ray ray = CreateRay(uv);

    // Visualize ray direction as color (RGB = XYZ)
    // This creates a gradient that changes with camera rotation
    float3 color = ray.direction * 0.5f + 0.5f;
    
    Result[id.xy] = float4(color, 1.0f);
}

// Ray structure definition
struct Ray
{
    float3 origin;
    float3 direction;
};

🧮 The Math Deep Dive

Why do we need the inverse matrices?

The standard rendering pipeline goes: World → View → Clip → Screen. But ray tracing needs to go backwards: Screen → Clip → View → World. That's why we use inverse matrices.

🧠 Mental Model

Think of projection like a camera taking a photo — it squashes 3D into 2D. The inverse projection "unsquashes" 2D back into 3D. The inverse view then moves those coordinates from "camera-relative" to "world-relative."

The Perspective Divide

After multiplying by the inverse projection, we get a 4D vector (x, y, z, w). The w component encodes depth information. We must divide by w to get back to 3D coordinates:

(x, y, z, w) → (x/w, y/w, z/w)

This is called the perspective divide and it's essential for correct perspective projection.

✅ Verification

When you run this, you should see:

  • A colorful gradient across the screen
  • Moving the camera changes the gradient (proving rays rotate)
  • Looking straight forward shows mostly blue (Z-forward in Unity)
  • Looking right shows more red (X-right in Unity)
  • Looking up shows more green (Y-up in Unity)

🐛 Common Bug

If the gradient doesn't change when you rotate the camera, check that you're passing the matrices every frame in SetShaderParameters() and that the camera GameObject has the RayTracingMaster script attached.

📚 What You Learned

🎓 Key Takeaways

• A ray is defined by an origin and a direction vector
• Pixels are unprojected using inverse camera matrices
• Compute shaders run one thread per pixel in parallel
• The perspective divide converts from 4D homogeneous to 3D coordinates
• Visualizing direction vectors as RGB colors is a great debugging technique
